#### 第4关：传播预测评估（必须填·不可跳过）

> **⚠️ 这是本次v3.0核心改动**：预测必须基于历史基准值，不得空填"待定"。
> **操作**：先判断内容类型 → 查基准值 → 填预测值 → 发布后对比实际值 → 复盘时填写差距分析。

**内容类型判断**（决定基准值）：

| 内容类型 | 典型案例 | 完播率基准 | 播放量参考 |
|---------|---------|:---------:|----------|
| 强情绪+冲突型（25-30秒） | 第11期/第25期 | **10-15%** | 1万-2万 |
| 强情绪+冲突型（35-45秒） | 第25期（40秒） | **8-12%** | 5千-1.5万 |
| 身份标签+强钩子（>40秒） | 第1期/第15期 | **4-6%** | 2万-4万 |
| 感悟/金句型 | 第19期 | **3-7%** | 500-2000 |
| 汇报/复盘型 | 第21期 | **3-4%** | 300-1000 |
| 方法论/干货型 | 第12期 | **2-5%** | 500-2000 |

**播放量预测公式**：
```
播放量基准 = 内容类型基准（见上表）
分享率预测 = 选题是否有"我要让XX看到这个"→ 有→基准×1.5；无→基准×0.5
情绪强度 = 是否有真实时刻/冲突对话→ 强→基准×1.3；弱→基准×0.8
最终预测播放量 = 基准 × 分享率系数 × 情绪系数
```

| 涨粉 | 预测值 | ___ | — | 结尾是否有系列钩子 |

> ⚠️ **悲观值说明（v3.4新增·2026-05-03·情商课第2期复盘教训）**：悲观值 = 预测值 × 0.7，用于风险兜底。方法论类/干货类内容执行层风险高，实际5秒完播极易跌到悲观值以下。若实际值低于悲观值，说明**执行层**（节奏/钩子/节奏前置）出了问题，需重拍或重剪。

## 核心规则

### 标题 + 简介 三要素关联规则

**核心原则**：标题/简介各自承担不同作用，信息不重复，组合形成完整钩子链。

**三步钩子链**：
```
标题 → 制造悬念/仪式感/期待
    ↓ 问出"是什么/为什么"
简介 → 提炼洞察，制造好奇（与口播不同！）
```

### 5. 📝 视频描述（简介）

**本质**：视频的第三道钩子，出现在折叠区。用户在看完标题+开头后是否点进来看完，取决于简介。

**核心原则**：
- 简介 ≠ 口播复述
- 简介 = 提炼视频里没说出口的那层洞察
- 制造好奇，不给答案

**好简介的标准**：

| 标准 | 说明 | 示例 |
|------|------|------|
| **提炼洞察** | 说出视频里用行动展示、但没直接讲出来的结论 | 口播："我没说，让他问龙虾" → 简介："授人以渔的最好方式，是不给他鱼" |
| **不剧透** | 不提前说出结果、答案、金句 | 口播金句是"龙虾就是AI时代最好的渔" → 简介里不要出现"龙虾"这个词 |
| **制造好奇** | 让用户想点进来看"然后呢/为什么" | "过了会儿，截图发回来了" → 制造悬念 |

**禁止**：
- ❌ 照抄口播原话（会剧透）
- ❌ 列3条干货要点
- ❌ 与标题重复信息
- ❌ "想知道的评论区留言"类营销话术

**底部固定格式**：
```
只说真话

#老陈说AI #AI #职场 #研发总监 #xxx（最多5个标签）
```

> **⚠️ 身份信息原则**：简介是否需要加入"三明学院/42岁研发总监"——取决于这个身份是否与本条视频的核心洞察相关。
> - 如果身份是洞察来源（比如学历影响判断、职业经历带来独特视角）→ 写
> - 如果身份与内容无关（比如讲龙虾工具，跟哪个学校出身无关）→ 不写
> - 原则：身份是洞察的背书，不是万能装饰
```

**分镜表模板**：

```
| 时间段 | 画面 | 说明 |
|--------|------|------|
| 0-3秒 | 近景直视镜头 | 开头钩子，不切 |
| 3-___秒 | ... | 按逐字稿节奏标注 |
| 结尾 | 近景 | "关注我"后渐黑 |
```

**分镜标注规则**：
- 困境排比/快切段：每句切一次Ken Burns放大→回原，制造节奏
- 段落转折（"那一刻/后来/于是"）：黑屏闪切0.3秒
- 金句/技巧命名：Ken Burns放大 + 重音效
- "不是…是…"句式：大字弹幕
- 总结页：字幕静止5秒，逐条弹出

## 附件C：内容输出双轨原则

**每个主题可选覆盖两个方向（单轨达标即可）：**

### D1：双重身份策略

**核心公式**：
```
双重身份 = 专家层（可信度） + 普通人层（共情力）
```

西门的设计：产品经理（专业背书）+ 普通人（刚学会AI，降低门槛）

老陈的适配：

| 身份层 | 适用内容 | 示例 |
|--------|---------|------|

### D2：西门式钩子类型（5种模式）

| 钩子类型 | 公式 | 示例（西门） | 老陈适配 |
|---------|------|------------|---------|
| **身份赋能型** | 只要你会X，就能做Y（门槛归零） | "只要会和AI聊天，就能搭网站" | "只要会用自然语言，就能写嵌入式代码" |

| **反常识翻转** | 说出预设恐惧+当场推翻 | "审美很重要——但我也没有审美" | "懂底层原理才能写好代码？不一定" |
| **成果数字型** | X个结果/Y天结果 | "三个视频涨粉5千" | "一个困扰我10年的问题，用一行代码解决了" |
| **信念宣言型** | 反直觉观点 | "敢想比敢做更重要" | "慢即是快，代码跑通不是目的" |

**⚠️ 规则**：钩子必须从逐字稿里找，不是写设计意图时自己编的。
**操作**：写完逐字稿后，扫描全文，标记每处钩子类型，密度≥每25秒1个钩子。

### D3：系列架构规则（依赖链设计）

> 来源：西门5集递进闭环（建站→部署→API→调研→传播），每集之间有依赖关系

**核心原则**：让观众看完第N集后想看第N+1集，因为第N集没有讲完。

| 系列类型 | 结构 | 适用场景 | 示例 |
|---------|------|---------|------|
| **递进依赖型** | N集环环相扣，不看后集会"断档" | 教程系列 | N→N+1→N+2必须顺序看 |
| **悬念钩子型** | 每集结尾预告下期具体内容 | 故事/洞察系列 | "下期拆XXX，关注我别错过" |
| **独立爆款型** | 每集单独完整，可单独传播 | 金句/嘴替型 | 不强依赖，单独也能火 |

**老陈合集适配**（嵌入式·系列结构示例）：

```
第1期：？ （待规划）
第2期：？ （待规划）
第3期：？
→ 系列必须是递进型
→ 第3期选题必须承接第2期的结论
```

**⚠️ 禁止**：每集结尾用"喜欢就关注"代替"下期预告"——前者价值感低，后者制造连续剧效应。

### D4：西门式教程结构（可直接套用）

> 参考：西门视频2「有手就行的AI编程」结构

```
【开场Hook】身份赋能型（10%时长）
  → 钩子：只要你会X，就能做Y

【自我介绍】30秒（5%时长）
  → 身份：专家层+普通人层
  → 模板："我是___，现在___，同时___。"

【工具介绍】先说"为什么需要"，再说"怎么用"（10%时长）
  → 禁忌：直接说"我来教你第一个工具"

【操作演示】屏幕录制+画外音（50%时长）
  → 关键：故意出错+修复 = 真实感制造
  → 禁忌：全程流畅无错——太假，观众知道是演的

【定制调整环节】（15%时长）
  → 展示"改细节"的过程，证明真的能个性化

【结尾钩子】（10%时长）
  → 固定格式："下一个视频，我会分享___。"
  → 禁忌："喜欢就关注"、"看到这里不容易"
```

**老陈适配示例**（嵌入式AI教程）：

```
【开场Hook】
"只要你会问问题，就能用AI写嵌入式代码。"

【自我介绍】
"我是老陈，19年嵌入式工程师。上周我让DeepSeek帮我写了一个驱动，
这是我第一次用AI写底层代码，有些地方还挺让我意外的。"

【工具介绍】
"做嵌入式开发最怕什么？不是写代码，是配环境。今天我用的是___。"

【操作演示】
（屏幕录制）
故意展示一个报错："我一开始这样问了，它给我返回了这个。"
"不对，我来改一下提示词。"
"好了，你看这样就对了。"

【结尾钩子】
"下期我会教大家怎么用AI查芯片手册，这个比写代码还省时间。"
```

### D5：门槛解构话术（老陈适配）

> 来源：西门"没有审美也能做"、"有手就行"

**公式**：
```
说出观众的预设恐惧 + 当场给出绕过方案
```

| 预设恐惧 | 西门的话术 | 老陈适配 |
|---------|-----------|---------|
| "没审美做不了" | "主播也没什么审美" | "懂底层原理才能写好？不一定" |
| "技术门槛太高" | "只要会聊天" | "只要会问问题" |
| "我不行" | "你必须行" | "工程师没有学不会的，只有没找到方法的" |
| "万一失败了" | "我就滚去吃shi" | "这套方法我用了三个月，不好用来骂我" |

### D6：痛点具象化技巧

> 来源：西门"和同事吃午饭不知道吃什么" → 把"选择困难"变成具体场景

**公式**：
```
抽象痛点 + 具体场景锚点
```

老陈适配示例：

| 抽象痛点 | 具象化表达 |
|---------|-----------|
| 嵌入式工程师焦虑 | "每天最怕的不是写代码，是领导说'这个方案要改'" |
| 技术焦虑 | "用了三年这套方案，从没问过为什么" |
| 年龄焦虑 | "35岁以后，我发现写代码越来越慢——不是我不行了，是方向不对" |
| AI焦虑 | "我不是怕被AI替代，是怕比我年轻的人用AI替代我" |
