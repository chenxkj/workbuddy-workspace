# 选题调研流程（AI辅助版）

> 版本：v1.0
> 日期：2026-04-27
> 适用场景：每期拍摄前做竞品/受众/平台算法调研
> 工具：内置 web_search + web_fetch（无需额外API）

---

## 一、为什么要调研

| 不用调研 | 用调研 |
|---------|--------|
| "我觉得这个方向可以" | "数据显示这类内容完播率X%" |
| 拍完发现是红海 | 提前找到差异化切入口 |
| 标题靠拍脑袋 | 标题有竞品数据支撑 |
| 方案版本来回改 | 第一版就接近最优解 |

**调研的核心价值**：减少拍脑袋，把"我觉得"变成"数据证明"。

---

## 二、调研标准流程（4步）

### 第1步：定义调研问题（5分钟）

拿到选题后，先问清楚：
- 这个选题想解决什么问题？
- 目标受众是谁？（程序员？家长？管理层？）
- 核心竞品是什么？（抖音同类视频）
- 最大的不确定性是什么？

格式化为3个具体搜索词：
```
调研词1：[竞品/同类内容]
调研词2：[受众痛点]
调研词3：[算法/平台特征]
```

---

### 第2步：多源搜索（10-15分钟）

执行3组平行搜索：
```
第一组：搜索竞品内容
  关键词：抖音 + 选题核心词 + 爆款/播放量
  工具：web_search（中文）

第二组：搜索受众痛点
  关键词：目标人群 + 核心痛点 + AI/工具
  工具：web_search（中文）

第三组：搜索平台算法特征
  关键词：抖音 + 内容类型 + 算法推荐/完播率
  工具：web_search（中文）
```

---

### 第3步：深度读取关键来源（10分钟）

从搜索结果中选2-3个最有价值的页面，用 web_fetch 深度读取：

选择标准：
- 有具体数据（不是泛泛而谈）
- 来源可信（知乎/公众号/行业媒体）
- 与选题直接相关

读取重点：
- 竞品内容：播放量/互动数据、内容结构、评论区情绪
- 受众痛点：真实需求表述、搜索词分布
- 算法特征：平台推荐逻辑、标签策略

---

### 第4步：综合报告 + 方案更新（10分钟）

输出调研结论：
```
1. 竞品现状：抖音上同类内容有多少，质量如何
2. 受众验证：选题痛点是否真实存在
3. 差异化机会：现有竞品的空白点
4. 标题优化建议：基于竞品数据的标题方向
5. 风险预警：是否有合规/同质化风险
```

把调研报告存到：`04_方案案例/第X期-调研报告.md`

---

## 三、调研评估标准

| 维度 | 评估问题 | 结果 |
|------|---------|------|
| 竞品饱和度 | 抖音上同类内容是否超过20条高质量视频？ | 超过→差异化难 / 未超过→有机会 |
| 受众真实性 | 搜索到的需求是真实的还是伪需求？ | 真实→继续 / 伪需求→换角度 |
| 时机 | 这个话题近期是否有热度上升趋势？ | 上升→借势 / 下降→谨慎 |
| 合规 | 话题是否有政策/平台敏感风险？ | 无→继续 / 有→换角度 |
| 差异化 | 你的切入角度是否与现有内容有明显不同？ | 有→继续 / 无→重新定位 |

---

## 四、与方案的关系

```
调研报告 → 写入第X期-调研报告.md
           ↓
方案文件（老陈视频标准化生产模板.md）需要：
  - 竞品差异化：标题/切入角度有数据支撑
  - 受众验证：选题痛点来自真实调研，不是拍脑袋
  - 风险预警：提前识别合规/同质化风险
           ↓
没有调研报告 = 方案评分扣10分
调研发现颠覆性结论 = 重新设计方案，不是硬拍
```

## 六、与之前Tavily调研的对比

| 维度 | Tavily调研（API版） | 本流程（内置工具版） |
|------|--------------------|--------------------|
| 工具依赖 | 需要API Key | 无需配置，直接用 |
| 搜索范围 | Tavily索引（英文优先） | DuckDuckGo（中文可用） |
| 执行速度 | 快（API调用） | 稍慢（需手动读源） |
| 输出质量 | 高（结构化） | 取决于搜索词质量 |
| Windows兼容 | ✅ | ✅ |
| 成本 | 需Tavily订阅 | 免费 |
| **推荐场景** | 大型调研/竞品深度分析 | **每期标配调研** |

**结论**：Tavily适合深度专项调研（竞品横向对比、平台算法专项研究），本流程适合每期标配调研。两者互补，不是替代关系。
