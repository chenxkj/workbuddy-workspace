## 一、开头公式（核心·来自dbs-hook）

### 黄金公式
```
开头 = 话题（讲什么）+ Hook（为什么看）+ 可信度（为什么信你）
```

### 老陈适配示例

| 组件 | 示例 | 说明 |
|------|------|------|
| 话题 | "选题和标题的区别" | 告诉用户要讲什么 |
| Hook | "我去年涨粉200万" | 制造吸引力 |
| 可信度 | "靠的就是搞清楚这个" | 建立信任 |
| **完整开头** | "我去年涨粉200万，靠的就是搞清楚选题和标题的区别" | 话题+Hook+可信度 |

### 老陈版开头公式

```
公式1：身份 + 数字 + 悬念
"三明学院出身，42岁研发总监，我用10天从2个粉丝做到288个——"

公式2：痛点 + 反问
"AI夸你的时候，你信吗？——我信了三个月，发现全是废话。"

公式3：反差 + 悬念
"善良的李亚鹏，认识半个娱乐圈，30年为什么赚不到钱？"

公式4：结果 + 反转
"播放264，完播5.79%，涨粉0——我接受。但这不是我要说的。"
```

## 二、开头的四大信条（来自dbs-hook）

### 信条1：开头是内容的试用装，不是标题的延续
- 开头必须**独立工作**
- 不能假设用户看了标题、看了封面
- 开头必须在**5秒内**独立建立吸引力

### 信条2：好开头公式
```
开头 = 话题 + Hook + 可信度
```
- 话题：告诉用户要讲什么
- Hook：制造"为什么看"的吸引力
- 可信度：建立"为什么信你"的信任

### 信条3：开头要制造悬念，不要直接给答案

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| AI夸你=骗你，**证明**AI不可信 | 给了答案 | AI夸你=骗你，**为什么**你还信？ |
| 他失败**证明**人脉不等于赚钱 | 说了结论 | 他失败，30年**为什么**还是没钱？ |

### 信条4：开头必须口播友好

| 错误写法 | 问题 | 正确写法 |
|----------|------|----------|
| 你以为你在自律？其实你只是在逃避执行 | 自问自答，念不出口 | 只要你没在执行，你的动作大概率就是逃避执行的借口 |
| 难道你不觉得XXX吗？ | 反问太多 | XXX |

## 三、内容质量自检（在优化开头之前）

### 3.1 内容完整性检查

| 检查项 | 标准 | 处理 |
|--------|------|------|
| 正文字数 | ≥200字 | 太少→警告 |
| 有无干货 | 有价值信息 | 没价值→停止 |

### 3.2 素材丰富度检查

从文案中查找以下5类素材：

| 素材类型 | 检查内容 | 优先级 | 老陈适配 |
|----------|----------|--------|----------|
| **数据冲击** | 大数字、对比数字 | ⭐⭐⭐⭐⭐ | 播放量、完播率、涨粉数 |
| **转变故事** | 之前vs之后，反差 | ⭐⭐⭐⭐⭐ | 三明学院→研发总监 |
| **金句** | 独立成立的观点 | ⭐⭐⭐⭐ | "只说真话" |
| **权威背书** | 人物、机构 | ⭐⭐⭐ | 腾讯、20年经验 |
| **痛点共鸣** | 目标人群的焦虑 | ⭐⭐⭐ | 转型焦虑、AI焦虑 |

### 3.3 诊断结果处理

| 素材数量 | 诊断结果 | 行动 |
|----------|----------|------|
| 0个 | 内容没有素材 | 停止，补充素材 |
| 1-2个 | 素材不够丰富 | 可以做，但开头冲击力受限 |
| 3个以上 | 素材丰富 | 继续优化 |

## 四、开头诊断维度（6项检查）

| 诊断维度 | 检查项 | 常见问题 |
|----------|--------|----------|
| **独立性** | 不看标题能理解吗？ | 假设用户看了标题 |
| **Hook** | 前5秒有抓手吗？ | 平铺直叙，没有数据/金句/反差 |
| **悬念** | 有没有直接给答案？ | 开头就说结论 |
| **可信度** | 为什么听你讲？ | 没有建立权威/成绩 |
| **口播友好** | 能直接念出来吗？ | 自问自答、书面语 |
| **匹配度** | 开头承诺的，正文能兑现吗？ | 标题说A，正文讲B |

## 五、生成优化方案（三种方法）

### 方法一：素材提取（优先级最高）

| Hook类型 | 示例 |
|----------|------|
| 晒结果+反转 | "10天从2粉到288个，很多人问我怎么做到的——其实我只是搞清楚了一件事" |
| 数据冲击 | "264播放，5.79%完播，涨粉0" |
| 反差/转变 | "从技术总监到抖音小白" |
| 金句 | "只说真话，不割韭菜" |
| 痛点+悬念 | "研究3个月AI，焦虑3年，后悔30年" |

### 方法二：素材增补

如果文案素材不够，主动增补：
- 真实数据或结果
- 具体案例或对比
- 反常识的结论

### 方法三：悬念制造

| 错误写法 | 正确写法 |
|----------|----------|
| 用了"证明" | 改成"为什么" |
| 直接给答案 | 用"问题"而不是"结论" |
| AI夸你=骗你，**证明**AI不可信 | AI夸你=骗你，**为什么**你还信？ |

## 六、完整脚本结构

```
┌─────────────────────────────────────┐
│  开头（0-5秒）                      │
│  话题 + Hook + 可信度               │
│  必须独立工作，5秒内建立吸引力      │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  痛点（5-10秒）                     │
│  说出目标人群的焦虑                  │
│  制造"说的就是我"的感觉             │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  正文（10-25秒）                    │
│  每5秒一个转折/爆点                  │
│  删除废话，只留核心观点              │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│  结尾（25-30秒）                    │
│  金句收尾 + 引导关注                │
│  不说"交作业"，改说"关注我"        │
└─────────────────────────────────────┘
```

## 九、短视频文案核心逻辑（2026-04-23新增）

> 来源：老陈文案教学复盘

### 9.1 共情的底层逻辑

**核心定义**：
> 我说了一句话，你有了感觉，你想参与，这叫共情。

| 要素 | 说明 |
|------|------|
| **共情** | 让人有感觉，想参与 |
| **自嗨** | 我抒发我想写的，不管别人听不听 |

**自检**：你的文案是让人"想参与"，还是只是"抒发自己想说的"？

---

### 9.2 说话逻辑 vs 短视频逻辑

| 说话逻辑 | 短视频逻辑 |
|----------|------------|
| 讲明白就行 | 让更多人参与 |
| 我在旁边你听得懂就行 | 我端了一锅，大家愿不愿意趴上来 |
| 平铺直叙 | 每句话都要让人"想参与" |

**核心区别**：
- 说话：我在跟你讲一件事，你听懂了就行
- 短视频：我端了一锅东西在煮，你要不要来趴着看

---

### 9.3 开头的正确逻辑

**错误认知**：开头要圆回来，要把事情讲完整

**正确认知**：
- 开头钩子只是**引起注意**
- 讲故事就是讲故事
- 不用圆回来
- 后续内容是**解释悬念**，不是圆故事

| 错误 | 正确 |
|------|------|
| "我活不过19岁...（后面要解释原因）" | "我活不过19岁" → 直接讲故事，不用解释 |
| 开头要完整 | 开头只要引起注意 |
| 前后要衔接 | 故事扩充是解释悬念 |

---

### 9.4 故事扩写的逻辑

**什么时候需要扩写？**
- 第一句话说完悬念后
- 观众问"为什么？"
- 用故事解释悬念

**扩写原则**：
- 讲故事，不用讲道理
- 别人看完故事，心里有自己的答案
- 不要把答案说出来

| 错误 | 正确 |
|------|------|
| 讲完故事，非要升华道理 | 讲完故事，让观众自己得答案 |
| "所以我们要..." | 不说，让观众自己感受 |
| 硬升华 | 这条视频的价值在于故事本身 |

---

### 9.5 结尾的正确逻辑

**错误**：结尾要升华、要说教、要把道理讲清楚

**正确**：
- 讲完故事，大家心里有答案了
- 不需要你再总结道理
- 简洁收尾

| 错误结尾 | 问题 | 正确结尾 |
|----------|------|----------|
| "所以我们要学会..." | 说教感 | 讲完故事就停 |
| "我淌过旁人..." | 沉醉诗情画意 | 观众自己得答案 |
| "这就是人生..." | 太升华 | 简洁，有个性就行 |

**老陈专属结尾**：
- ✅ "这就是我的性格"
- ✅ "我不是来讲故事的，我是来告诉你的"
- ❌ "重构你的信念系统底层代码"（太升华）

---

### 9.6 深度视频 vs 短平快视频

| 类型 | 时长 | 核心要求 |
|------|:----:|----------|
| 短平快 | 25-30秒 | 每5秒一个爆点 |
| 深度视频 | 4-5分钟 | 有故事、有反转、每1分钟一个爆点 |

**深度视频结构**：
```
开头钩子(30秒) → 困境故事(60秒) → 反转发现(30秒) 
→ 干货技巧(90秒) → 实战效果(40秒) → 简洁结尾(20秒)
```

**深度视频注意事项**：
1. 开头用**自己的真实经历**，不是"朋友"的故事
2. 技巧部分不能太满，每个技巧25-30秒
3. 结尾不升华，简洁收尾
4. 不要沉醉在诗情画意里

| "控制情绪" | "情绪权限管理" | 系统安全 |

## 十一、钩子·埋点·转折点 吸引力评估规范

> **来源**：NLP专场v5分析经验（2026-04-23）

### 11.1 三维度定义

| 维度 | 定义 | 作用 | 优秀标准 |
|------|------|------|----------|
| **钩子（Hook）** | 让人"想继续看下去"的点 | 拉留存 | 每30秒1个 |

### 11.9 结尾人设锚点规范

**老陈专属结尾必须包含**：
- "我是老陈"（人设）
- "只说真话"或"教真东西"（价值锚点）

| 错误结尾 | 正确结尾 |
|----------|----------|
| "这就是我用的方法" | "我是老陈，只说真话" |
| "关注我，下期见" | "我是老陈，关注我，下期见，只说真话" |
| "重构底层代码" | "我是老陈，18年程序员，只说真话" |

**人设结尾标准结构**：

## 十二、好文案的三层评判标准

> **来源**：内容创作专家 × NLP专场v6实战经验
> **日期**：2026-04-23

### 12.1 好文案只有一个标准

**让人想读完、想行动、想转发。**

---

### 12.2 三层标准

#### 第一层：让人停下来

标题/开头能不能抓住注意力。

| 标准 | 说明 | 错误示范 |
|------|------|----------|
| 不是"震惊体" | 是**精准戳痛点** | "必看！不看后悔！" |
| 不是"必看" | 是**看了对我有什么用** | "干货来了" |
| 悬念不是编造的 | 是**真实存在的张力** | 伪悬念 |

#### 第二层：让人读进去

正文能不能让人沉浸。

| 标准 | 说明 | 错误示范 |
|------|------|----------|
| **具体不要抽象** | "被否定"比"职场不顺"有力一百倍 | 泛泛而谈 |
| **有画面感** | 让人脑子里能放电影 | 纯概念 |
| **节奏感** | 长短句交错，停顿留白 | 一直长句 |
| **不说废话** | 每一句都推进 | 凑字数 |

#### 第三层：让人记住、转发、行动

读完之后留下了什么。

| 标准 | 说明 | 错误示范 |
|------|------|----------|
| **一句话能复述** | 核心观点能被一句话概括 | 看完啥都记不住 |
| **有获得感** | 读完觉得自己学到了 | 白开水 |
| **有情绪余韵** | 读完了还在想 | 看完就忘 |

## 十三，开头钩子详解

> **来源**：内容创作专家
> **日期**：2026-04-23

### 13.1 核心原理

人脑每天处理的信息量巨大，会自动过滤。能让大脑停下来的只有两件事：

| 触发 | 说明 |
|------|------|
| **威胁** | 危险信号，大脑必须注意 |
| **未完成** | 悬念，大脑想补完 |

**好开头不是"精彩"，是制造未完成的张力。**

---

### 13.2 五种高效开头模式

#### 1. 冲突开场

把矛盾直接摆出来，不解释。

```
例：有个工程师跑来找我，说他经理是个傻逼。
产品经理天天加需求，经理只会说"你先做"。
```

**你的脚本用的就是这种**。冲突够大，够真实。

---

#### 2. 反常识开场

说一个大家都知道的结论，然后打碎它。

```
例：有人说，努力就有回报。
但我见过太多拼命干活的人，十年过去了，还是基层。
```

大脑被"不对啊"卡住，想往下看。

---

#### 3. 场景开场

描述一个具体画面，让人代入。

```
例：凌晨两点，你在工位上。
刚改完第三版需求，产品发来消息："不好意思，需求又变了。"
```

越具体越好，不要"有时候工作压力很大"这种废话。

---

#### 4. 数字开场

具体数字自带冲击力。

```
例：我见过100个程序员离职，90个都犯了同一个错误。
```

数字要真实，虚构的数字会被骂。

---

#### 5. 身份代入开场

第一句话就锁定目标读者。

```
例：写代码的人，最怕的不是bug。
是有人在你背后说：这人技术可以，情商不行。
```

读者看到"写代码的人"，立刻觉得"这是在说我"。

---

### 13.3 开头的死法

| 死法 | 问题 |
|------|------|
| 以"随着"开头 | 老派，催眠 |
| 以"首先"开头 | 这是报告不是短视频 |
| 以"大家好"开头 | 你谁啊，我不关心 |
| 以"今天我要讲"开头 | 平淡如水，注意力直接散 |
| 以"相信大家都有过"开头 | 没人相信，没人有耐心 |

## 十四，正文节奏详解

> **来源**：内容创作专家
> **日期**：2026-04-23

### 14.1 核心原理

人脑讨厌无聊，喜欢**变化**。

| 状态 | 问题 |
|------|------|
| 一直紧张 | 会累 |
| 一直平淡 | 会困 |

**好节奏：紧张→放松→紧张→放松，螺旋上升**

每一段都要有存在的理由：要么推进，要么共鸣，要么转折。

---

### 14.2 节奏控制的五个工具

#### 1. 长短句交替

短句有力，长句渲染。

```
短：你被否定了。
长：那天你写了一千行代码，改了两天，通宵了两次，
    上线之后产品说——这不行。
```

短句制造冲击，长句制造共鸣。一直短句会累，一直长句会困。

---

#### 2. 停顿留白

不是每句话都要无缝衔接。

```
我很长时间都在想这个问题。
（停顿）
为什么我会被这些话点燃？
```

停顿让观众有时间消化，也有制造悬念的作用。录视频时停顿两秒，流量会涨。

---

#### 3. 转折词要狠

"但是""其实""不是"这种转折词是节奏放大器。

**用的技巧：铺垫三句，转折一句。**

```
你写了一千行代码。✓
改了三版需求。✓
有人说"重做"。✓
（停顿）
你什么感觉？
```

铺垫是蓄力，转折是释放。铺垫不够，转折就轻。

---

#### 4. 具象不抽象

抽象的词没有画面感，大脑会跳过。

| 抽象 | 具象 |
|------|------|
| 职场压力很大 | 产品说需求又变了，你改到凌晨两点，第三版上线后他说：算了这个功能不要了 |
| 情绪会影响判断 | 你气得手在抖，你知道自己在想什么，但你说不出来 |

越具体越真实，越真实越有代入感。

---

#### 5. 金句密度

金句是让人截图转发的理由。每隔一段要有一句让人想记下来的话。

**你的脚本金句**：
- "我像个没有root权限的进程"
- "情绪问题不是性格问题，是技术问题"
- "掌握情绪的编译权"

这几句单独拎出来都能转发。金句是钩子+转发理由，要刻意设计。

---

### 14.3 正文的结构模式

#### 情绪递进式

痛点一层比一层深。

```
你被说代码不行 → 你被否定努力 → 你被说情商低
每一层都是叠加的情绪，不是并列的
```

#### 问题解决式

困难→转折→方案。

```
描述困境 → 发现本质 → 给出方法
这个结构适合干货内容
```

#### 故事线式

用叙事带动说理。

```
先讲一个完整的故事，在故事里埋干货
故事有弧度，干货不干
```

**你的脚本是三种的混合，这是高手做法。**

## 十五，结尾设计详解

> **来源**：内容创作专家
> **日期**：2026-04-23

### 15.1 核心原理

心理学上有个"峰终定律"：人对一段体验的评价，取决于最高峰和结尾时刻。

**结尾没力度，前面再好也白费。**

---

### 15.2 四种强结尾模式

#### 1. 价值总结型

把核心收获用一句话说清楚。

```
这就是程序员的情商：不是八面玲珑，是用技术手段掌握情绪的编译权。
```

要精准，要有力，要经得起推敲。

---

#### 2. 行动号召型

明确告诉读者下一步做什么。

```
关注我，下期我讲为什么你总遇到傻逼领导。
```

**你的脚本用人设结尾 + 悬念引导。**

---

#### 3. 金句定格型

用一个漂亮的句子结束，让人回味。

```
你不是在和老板对抗，你是在和老板的程序对抗。
```

这种结尾适合金句密度高的内容。

---

#### 4. 情感升华型

从一个具体的点，升华到更大的共鸣。

```
技术能解决代码问题。
但能解决情绪问题的，只有你自己。
```

适合情绪向内容，收尾要有力量。

---

### 15.3 结尾的死法

| 死法 | 问题 |
|------|------|
| 以"以上就是今天的全部内容"结尾 | 自杀 |
| 以"感谢观看"结尾 | 你在告别谁 |
| 以"有问题可以在评论区留言"结尾 | 让人不知道说什么 |
| 突然结束，没有收尾感 | 让观众莫名其妙 |

| **30秒** | 0-3秒强钩子 → 3-15秒冲突/痛点 → 15-25秒干货/反转 → 25-30秒结尾/悬念 |
| **60秒** | 0-5秒身份钩 → 5-20秒故事/痛点 → 20-45秒技巧/反转 → 45-55秒强化 → 55-60秒悬念 |
| **4分钟+** | 0-10秒强钩 → 10-30秒背景 → 30-180秒正文（每5秒一个转折）→ 180-220秒案例 → 220-240秒总结 → 240-270秒悬念结尾 |

**使用建议**：
- ✅ 快速出稿：用它生成初稿
- ✅ 结构参考：学习脚本结构
- ❌ 人设强化：需要手动加强（参考v7模板）
- ❌ 钩子密度：v7的13个钩子它达不到

#### 核心能力

| 能力 | 评分 | 说明 |

| 老陈适配 | ⭐⭐⭐ | 有导流词检测，缺少薪资/极限词专项 |
| 准确性 | ⭐⭐⭐ | 有误报，需人工复核 |

#### Skill精华

**词库来源**：
- `konsheng/Sensitive-lexicon`：广告、政治、暴恐、色情、涉枪涉爆、补充词库
- `bigdata-labs/sensitive-stop-words`：广告、政治、色情、涉枪涉爆
- `jkiss/sensitive-words`：广告、政治、色情

**检测命令**：
```bash
# 设置UTF-8编码后运行
$env:PYTHONIOENCODING="utf-8"; python "C:\Users\86151\.workbuddy\skills\douyin-forbidden\scripts\check.py" -f "方案.md"
```

**风险词分类**：
| 类型 | 标记 | 处理方式 |
|------|------|----------|
| 🔴 违禁词 | 平台明令禁止 | **必须改** |
| 🟡 广告极限词 | 最/第一/顶级 | 建议改 |
| 🟠 平台限流词 | 私信/加微信/收徒 | 规避表述 |

**改写建议**：
- 谐音替换：最牛 → 真的强
- 符号分割：私信 → 关注后私信
- 同义替换：傻逼 → 态度有问题的人

#### ⚠️ 误报提醒（实测）

| 风险词 | 实际判断 | 说明 |
|--------|----------|------|
| **MA** | ❌误报 | "关注引导MAX"的缩写，不是违禁词 |
| **涨粉** | ⚠️可接受 | 数据记录中正常使用 |
| **第一** | ⚠️可接受 | "第一个"中可使用 |
| **彻底** | ❌误报 | 正常用语 |

**结论**：词库偏通用，**自建词库（07_违规词库.md）必须保留**，用于：
1. 替换方案（带✅合规替换）
2. 老陈专属规则（薪资/导流/极限词）
3. douyin-forbidden做快速扫描，人工复核
