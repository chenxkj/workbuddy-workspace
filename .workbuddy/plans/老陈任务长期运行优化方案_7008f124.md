## 需求

1. 可自主进化迭代 — 同类错误不重复犯，用户纠正自动记住，下次直接用
2. 尽量减少内存占用 — 不用大文件堆叠，改用增量追加结构
3. 独立任务记忆文件 — 所有数据在任务本地，不进全局
4. 不污染其它任务 — 已通过全局/本地 USER/SOUL 分离解决，本方案不涉及

## 当前问题

- MEMORY.md 采用"末尾追加"模式，长期运行会无限膨胀
- 每期发布后的数据/反馈散落在对话中，无法复用
- 没有自动捕获用户纠正的机制，每次都要手动更新
- 日志文件（YYYY-MM-DD.md）本质冗余，不产生价值

## 目标状态

记忆体系 = 固定核心文件（不变）+ 增量追加文件（只增不减）
进化机制 = 对话开始读索引 → 对话中捕获纠正 → 对话结束更新索引

## 记忆文件架构（全部在任务本地 .workbuddy/ 下）

.workbuddy/
├── SOUL.md              # 任务灵魂，固定不增长，写死人设和风格
├── USER.md              # 用户信息，固定不增长，写死老陈个人资料
└── memory/
├── INDEX.md         # 索引（永远 <5KB，每次只追加新条目）
├── corrections.jsonl # 用户纠正记录（每行一条，永不重写历史）
├── best_practices.jsonl # 最佳实践（每行一条，永不重写历史）
├── errors.jsonl      # 执行错误记录（每行一条，永不重写历史）
└── episodes/         # 每期发布后的数据/反馈记忆
├── D1.md
├── D4.md
└── ...

## 进化流程（对话级自动闭环）

每次对话分三步：

Step 1 — 对话开始（读取）
→ 读 INDEX.md → 加载 corrections/best_practices/errors 全部 jsonl 行
→ 加载 INDEX.md 中的账号信息 + 最新教训摘要

Step 2 — 对话中（捕获）
→ 捕获用户纠正 → 追加到 corrections.jsonl（一行 JSON）
→ 捕获最佳实践 → 追加到 best_practices.jsonl
→ 捕获执行错误 → 追加到 errors.jsonl

Step 3 — 对话结束（写入）
→ 更新 INDEX.md（仅追加新条目摘要，不重写全文）

## INDEX.md 规范（永远不超过 5KB）

内容 = 账号固定信息（<2KB）+ 最新教训摘要（<3KB）
结构：

- 账号/定位/红线/流程（固定，每次直接读）
- corrections 最新5条摘要
- best_practices 最新3条摘要
- errors 最新3条摘要

## corrections.jsonl 示例行

{"ts":"2026-04-13","type":"correction","topic":"脚本结尾","wrong":"老陈说实话，就这样","correct":"我是老陈，只说真话。","source":"老陈反馈"}
{"ts":"2026-04-14","type":"correction","topic":"记忆架构","wrong":"MEMORY.md无限追加","correct":"改用JSONL+INDEX结构","source":"任务优化"}

## errors.jsonl 示例行

{"ts":"2026-04-13","type":"error","action":"delete_file","target":"brain目录旧文件","error":"工具无法操作AppData目录","fix":"改用PowerShell命令"}
