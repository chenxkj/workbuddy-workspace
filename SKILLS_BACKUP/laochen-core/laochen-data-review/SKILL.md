# 老陈抖音·数据复盘 Skill

> **职责边界**：只负责分析已发布视频的数据，反向修正流水线，不写新文案
> **触发词**：做复盘/数据/分析这条视频
> **对应规范**：`抖音账号运营模板包/01_模板文件/老陈视频标准化生产模板.md` 复盘相关章节

---

## 一、环境检查（前置条件）

本 Skill 不绑定特定模型。执行前只检查当前环境是否能读取账号项目的数据文件、预测文件和方案文件。

若当前环境无法读取必要文件，立即中断并说明缺哪个文件；不要凭记忆复盘。

必须确认：
- 数据文件可读，且未超过当前账号项目声明的过期阈值
- 盲预测或方案预测段可读，只读不改
- 逐字稿/方案文件可读，复盘结果写回该文件
- 当前账号数据路径来自项目入口文件，不来自本 Skill 的硬编码

## 三、复盘阅读顺序强制规范（v5.11新增·方案A核心）

> **根因**：先读稿子再做复盘 → 自动用稿子逻辑解释数据（后视偏差）。
> **解决**：强制数据先行——先读数据文件和盲预测，最后读稿子。

### 三.1 强制阅读顺序

复盘时必须严格按顺序读取文件，**不可颠倒**：

| 顺序 | 读取内容 | 读取目的 | 禁止 |
|:----:|:---------|:---------|:-----|
| ①第一 | 数据文件（播放量/完播率/2秒跳出率/互动数据） | 建立客观基准，不被稿子影响 | 禁止先读稿子 |
| ②第二 | 盲预测文件（predictions/xxx.md） | 对比预测vs实际，不修改预测 | 禁止修改预测文件 |
| ③最后 | 逐字稿文件 | 找稿子层面的根因（中段节奏/钩子质量） | 禁止用稿子解释数据 |

### 三.2 数据先行验证逻辑

读完三类文件后，必须回答以下问题（写入复盘报告）：

1. "实际数据是否验证了盲预测？" → 吻合/偏差___%
2. "如果只看数据（不读稿子），我会得出什么结论？" → ___
3. "读稿子后，我是否在用稿子解释数据？" → 是（❌偏差）/ 否（✅客观）

### 三.3 禁止事项

| 禁止行为 | 后果 |
|:-----|:---------|
| 先读稿子再做复盘 | 后视偏差→用稿子合理化数据→复盘无效 |
| 用稿子内容解释数据表现 | 掩盖真实根因→无法修正流水线 |
| 修改盲预测文件 | 破坏校准循环→预测失去意义 |

## 三附、校准自动触发机制（吸收自CHEAT·v5.4增补）

> **根因**：复盘偏差>30%是"症状"，但"是否系统性"需要累积判断。CHEAT用`consecutive_directional_errors[]`追踪同向偏差，满足阈值时自动提议bump。
> **解决**：复盘时自动更新偏差队列，满足触发条件时输出提议，不等老陈手动发现。

### 三附.1 偏差方向判定

每次复盘后，按"实际播放 vs 预测中枢"判定方向：

| 情况 | 方向 | 记录 |
|:-----|:-----|:---|
| 实际 > 中枢 +25% | `low`（预测低估） | `consecutive_directional_errors.push("low")` |
| 实际 < 中枢 -25% | `high`（预测高估） | `consecutive_directional_errors.push("high")` |
| 在 ±25% 内 | `neutral` | 清空队列 → `consecutive_directional_errors = []` |

**偏差幅度记录**（用于后续判断）：
```
deviation_magnitude: 实际 / 中枢（如 0.3x = 严重高估，3.0x = 严重低估）
```

### 三附.2 触发判断（不是死磕"≥3次"）

Claude判断（不是固定门槛）：

| 触发信号 | 动作 |
|:---------|:-----|
| 连续同向 ≥3 次 | 提议 bump |
| 1次极端偏差（≥10x 或 ≤0.1x） | 提议 bump（"一次性强信号"） |
| 2次同向 + 评论区出现一致反向证据 | 提议 bump（"评论+数据双信号"） |
| 3次同向但每次偏差都很小（<25%） | 不提议（可能是噪声） |
| 偏差跨多个维度无清晰方向 | 不提议（不知道改什么） |

**输出格式**（触发时）：

```
🚨 检测到校准偏差信号：

[类型]：连续 N 次同向 / 1次极端（Xx） / 评论+数据双信号
[偏差队列]：["high", "high", "high"]
[最近偏差]：第X期 实际 vs 中枢 = 0.3x（严重高估）

建议：跑 `/cheat-bump` 看是否需要升级评分公式。
（如不想现在处理，说"跳过"，队列继续累积）
```

### 三附.3 状态管理

复盘完成后，更新`.cheat-state.json`：

```json
{
  "calibration_samples": "<+1>",
  "consecutive_directional_errors": ["high", "high", "low", ...],
  "last_retro_at": "<ISO timestamp>",
  "last_retro_deviation": "<实际/中枢比值>"
}
```

`cheat-bump`执行后，清空队列：
```json
{ "consecutive_directional_errors": [] }
```

### 三附.4 与现有流程的集成

| 位置 | 动作 |
|:-----|:-----|
| 步骤2（偏差根因分析）后 | 判定方向 → 更新`consecutive_directional_errors` |
| 步骤5（规范更新建议）后 | 检查触发条件 → 如满足，输出bump提议 |
| 写入`.cheat-state.json`前 | 确认`consecutive_directional_errors`已更新 |
| 步骤7（归档） | 方案文件从待拍摄/→已发布/·更新MEMORY.md |

**不阻塞复盘流程**：提议bump是"建议"，不是"必须"。老陈说"跳过"→继续，队列保留。

## 执行流程

### 步骤0：阅读顺序确认（方案A强制·必须最先执行）

**执行前必须确认已按顺序读完以下文件，未读则停止复盘**：

| 顺序 | 已读？ | 文件 |
|:----:|:------:|:-----|
| ① | □ | 数据文件（播放量/完播率/2秒跳出率/互动数据） |
| ② | □ | 盲预测文件（predictions/xxx.md，只读不修改） |
| ③ | □ | 逐字稿文件 |

**确认后方可进入步骤0.5**，未确认→输出以下提示并停止：
```
[阅读顺序未满足·复盘中止]
请先按以下顺序读取文件：
1. 数据文件（建立客观基准）
2. 盲预测文件（predictions/xxx.md，只读不修改）
3. 逐字稿文件（最后读，避免后视偏差）
确认三步都完成后，重新说"做复盘"。
```

### 步骤0.5：盲验验证（强制·不可跳过）

> **目的**：验证预测是否是真正的盲预测，防止 contaminated 数据进入校准池。
> **来源**：`laochen-view-prediction` 八附.4 接口要求。

**执行顺序**（接在步骤0之后、步骤1之前）：

| 顺序 | 验证项 | 方法 | 失败处理 |
|:----:|:---------|:-----|:---------|
| ① | **时间戳验证** | 预测段 `updated` 时间 < 视频发布时间 | 失败 → 标注 `[reconstructed]` |
| ② | **内容隔离验证** | 预测段不包含播放量/完播率等实际数据 | 失败 → 标注 `[contaminated]` |
| ③ | **不可变验证** | 预测段写入后无后续 edit 记录（或 edit 仅为"复盘"段） | 失败 → 标注 `[modified-post-hoc]` |

**输出位置**（复盘段第一行·强制）：

```
**盲验结果**：✅ 通过 / ❌ 失败（原因：[reconstructed/contaminated/modified-post-hoc]）
```

**失败处理**：
- ✅ 通过 → 继续步骤1（正常复盘）
- ❌ 失败 → 本次复盘数据**不计入** rubric 校准池，在数据填入表注明"⚠️ 盲验失败，不计入校准"

**修改读取顺序**（步骤0表格增加第④步）：

| 顺序 | 已读？ | 文件 |
|:----:|:------:|:-----|
| ① | □ | 数据文件（播放量/完播率/2秒跳出率/互动数据） |
| ② | □ | 盲预测文件（方案文件中的`## 预测`段落，只读不修改） |
| ③ | □ | 逐字稿文件 |
| ④ | □ | **盲验验证**（检查时间戳/内容隔离/不可变） |

**确认后方可进入步骤1**，未通过盲验→标注失败原因，继续复盘但不计入校准池。

### 步骤2：偏差根因分析

基于 `laochen-script-scoring` skill 规范诊断：

| 检查项 | 实际表现 | 判断 | 说明 |
|--------|----------|:----:|:------|
| 2秒跳出率 | ___% | 🔴/🟡/🟢 | >30%→开头钩子失效；15-30%→一般；<15%→优秀 |
| 5秒完播率 | ___% | 🔴/🟡/🟢 | 低于预测→开头未留住人 |
| 整体完播率 | ___% | 🔴/🟡/🟢 | 对比内容类型基准值判断 |
| 播放量 | ___ | 🔴/🟡/🟢 | 对比预测值判断 |
| 分享率 | ___% | 🔴/🟡/🟢 | 0%→传播动力未激活 |
| 评论率 | ___% | 🔴/🟡/🟢 | 0%→无参与接口 |

**根因归类**：

| 根因类型 | 判断标准 | 典型表现 |
|---------|---------|---------|
| 执行层问题 | 2秒跳出率高/5秒完播低 | 口播念稿感、节奏拖沓、表情不匹配 |
| 内容层问题 | 完播率低但2秒跳出正常 | 中段无聊、无悬念、说教感 |
| 发布层问题 | 播放量远低于预测 | 发布时间差、标签不对、描述不佳 |
| 品类诅咒 | 方法论类完播4-8% | 内容类型本身逆算法 |
| 互动设计问题 | 评论率/分享率=0 | 无参与接口、无争议点 |

### 步骤3：方案评审回溯（核心创新）

**核心问题**：为什么做方案时没发现这些问题？是流程漏洞还是执行漏洞？

**回溯检查清单**：

| 检查项 | 问题 | 根因归类 | 归属环节 |
|--------|------|---------|---------|
| 调研评审是否漏判了内容类型？ | 预测基准值选错 | 调研skill漏洞 | 主题调研评审 |
| 文案生成时是否忽视了三不说教？ | 逐字稿有问题但L2没扫出来 | 文案skill漏洞 | 文案生成 |
| 评分时是否高估了某维度？ | 评分偏差 | 评分skill漏洞 | 内容评分 |
| 预测值是否过于乐观？ | 预测机制缺陷 | 预测规范漏洞 | 主题调研评审 |
| 执行层问题是否被遗漏？ | 方案未覆盖执行层 | 方案模板漏洞 | 方案生成 |
| 互动设计是否被忽略？ | 无参与接口 | 文案/方案漏洞 | 文案生成/方案生成 |

**归类规则**：
- 如果是**流程设计问题**（如规范缺了某个检查项）→ 提出规范更新建议
- 如果是**执行问题**（如评分时手软了）→ 记录为执行偏差
- 如果是**不可预测因素**（如算法调整）→ 记录为外部变量

## 纪律

1. **不单独建报告**：所有复盘分析写入原方案文件
2. **数据先行（方案A强制）**：必须先读数据文件 → 再读稿子，禁止用稿子解释数据
3. **初步数据要标注**：未过48小时的数据必须标注"初步"
4. **规范更新需确认**：发现规范问题时提出建议，等老陈确认后更新
5. **踩坑记录要持续**：每条踩坑都要写入独立踩坑文件
6. **诚实面对数据**：不美化、不找借口
7. **复盘后归档**：方案文件从待拍摄/→已发布/·不可跳过
8. **复盘后写入记忆宫殿**：偏差>30%时，调用 `mempalace-auto-sync/scripts/sync_mempalace.py --mode incremental` 将根因+对策写入 MemPalace（laochen-orchestrator 触发点#10）
9. **⛔ 盲验失败不计入校准池**：步骤0.5盲验失败 → 复盘继续但不计入rubric校准，表格标注"⚠️ 盲验失败"
