# 老陈抖音·多Agent协同流水线 Skill（v1.1·自动模式）

**目标**：将6个独立Skill（topic-research / script-writing / script-scoring / plan-generator / data-review / account-review）协同为自动化流水线。

---

## 一、触发条件

以下任一触发词：

| 触发词 | 说明 |
|:---------|:-----|
| `开始制作新视频·主题是XXX` | 完整流水线启动 |
| `启动流水线` | 从指定阶段恢复 |
| `/orchestrate` | 命令行触发 |
| `多Agent协同` | 自然语言触发 |

## 一.五、执行模式（v1.1新增·来源：老陈反馈·2026-05-15）

### 两种模式

| 模式 | 规则 | 适用场景 |
|:-----|:-----|:--------|
| **自动模式（默认）** | 钩子确认后全自动跑到底。只在评分<90需重写、或最终方案需要审核时停下。 | 日常制作 |
| **手动模式** | 每个阶段完成后暂停，等待用户确认再推进。 | 探索性选题/高风险方向 |

### 自动模式下的暂停节点

| 节点 | 暂停条件 | 不暂停条件 |
|:-----|:--------|:----------|
| 钩子确认 | **必停**（钩子决定方向） | — |
| 稿子审核 | — | 评分≥90→自动进入方案生成 |
| 方案生成 | 评分<90需改稿重评 | 评分≥90→自动生成方案 |
| 最终交付 | 方案生成后→输出文件→告知用户 | 不停，直接输出 |

### 自动模式行为

1. 钩子确认→立即进入阶段2写稿（不等用户说"继续"）
2. 写稿完成→立即启动双盲评分（不等用户审核稿子）
3. 双盲评分≥90→立即进入阶段4生成方案（不等用户确认评分）
4. 双盲评分<90→暂停，输出修改意见，等用户决定是否改稿重评
5. 方案生成后→输出文件，告知用户"流水线完成·等待拍摄"

### 手动模式行为

每个阶段完成后输出进度报告+等待用户说"继续"。触发方式：用户在启动时说"手动模式"或"每步确认"。

## 三、完整流水线

### 阶段1：选题分析（Orchestrator 主会话）

```
输入：用户需求（"开始制作·主题是XXX"）
  ↓
调用 laochen-topic-research skill
  ↓
输出：选题评估报告（7关否决 + 钩子方案 + 播放量预测）
  ↓
判断：7关是否全部✅通过？
  ├─ ✅ 通过 → 进入阶段2
  └─ ❌ 否决 → 停止，输出否决原因，等待用户决策
```

**执行细节**：
- 读取 `MEMORY.md` 获取历史数据锚点
- 生成钩子选项（3-5个），等待老陈确认1个
- 执行7关否决制，全部通过才能推进
- 输出文件：`03_选题评估/选题-YYYYMMDD-主题关键词.md`

---

### 阶段2：文案生成（Orchestrator 主会话）

```
输入：选题评估报告 + 已确认钩子
  ↓
调用 laochen-script-writing skill
  ↓
执行：战略三步法 → 品类适配结构 → L1/L2/L2b/L3检查
  ↓
输出：纯净口播逐字稿 + 情绪节奏图
  ↓
执行4.5字数锚定检查（强制·不可跳过）
  ├─ ✅ 在目标字数范围内 → 进入阶段3
  └─ ❌ 超限 → 立即进入L2b砍字模式，砍到范围内才能继续
```

**执行细节**：
- 钩子从选题报告读取，**一字不动**抄入逐字稿开头
- 品类判断（A/B/C/D）→ 选对应结构
- 写稿完成后**不评分**，输出提示语引导用户开新会话评分
- **关键**：按v5.11规范，写稿Agent不评分，评分必须在新会话执行

---

### 阶段3：内容评分（双盲评审·独立Agent）

```
Orchestrator 启动 评分专家A（独立Agent·新会话）
  ↓
评分专家A 读稿子文件（不参考写稿上下文）
  ↓
输出：评分卡A（包含盲评确认字段）
  ↓
Orchestrator 启动 评分专家B（独立Agent·新会话）
  ↓
评分专家B 读稿子文件（不参考写稿上下文）
  ↓
输出：评分卡B（包含盲评确认字段）
  ↓
Orchestrator 计算差值 = |评分A - 评分B|
  ├─ 差值 ≤ 10分 → 最终得分 = (A+B)/2
  └─ 差值 > 10分 → 触发仲裁官 Agent
                    ↓
              仲裁官读稿子（独立Agent·新会话）
                    ↓
              最终得分 = 三次评分的中位数
  ↓
判断：最终得分 ≥ 发布阈值（A/B/C/D类均≥90分）？
  ├─ ✅ ≥90分 → 进入阶段4
  ├─ ❌ <90分 → 返回阶段2（带修改意见）
  │              循环直到≥90分 或 重试≥3次
  └─ 重试≥3次 → 升级，生成失败报告，等待用户决策
```

**执行细节（关键·盲评隔离）**：

评分专家A和B必须在**完全独立**的Agent会话中执行：

```
Orchestrator 调用方式：

使用 Agent tool 启动评分专家A：
  subagent_type: "general-purpose"
  prompt: "你是评分专家A。请执行以下步骤：
1. 读文件：{逐字稿文件路径}
2. 调用 /评分 或 laochen-script-scoring skill
3. 严格遵守盲评规范：不参考任何写稿上下文
4. 评分卡必须包含「盲评确认：✅ 未参考写稿上下文」字段
5. 输出评分卡"

等待评分专家A返回评分卡A...

使用 Agent tool 启动评分专家B：
  subagent_type: "general-purpose"
  prompt: "你是评分专家B。请执行以下步骤：
1. 读文件：{逐字稿文件路径}
2. 调用 /评分 或 laochen-script-scoring skill
3. 严格遵守盲评规范：不参考任何写稿上下文
4. 评分卡必须包含「盲评确认：✅ 未参考写稿上下文」字段
5. 输出评分卡"

等待评分专家B返回评分卡B...

计算差值，判断是否触发仲裁。
```

**禁止事项**：
- ❌ 评分专家A和B在同一个会话中执行
- ❌ 评分Agent的上下文中包含写稿历史
- ❌ 跳过差值检查直接取平均分

---

### 阶段4：方案生成（Orchestrator 主会话）

```
输入：选题评估报告 + 逐字稿 + 评分卡
  ↓
调用 laochen-plan-generator skill
  ↓
执行：预尸检（Plan for Failure）
  ↓
判断：预尸检是否通过？
  ├─ ✅ 通过 → 输出完整方案文件（11项交付物）
  └─ ❌ 未通过 → 判断预案类型
                    ├─ 拍摄执行类 → 写入分镜说明/拍摄注意事项
                    └─ 稿子修改类 → **返回阶段2**（改稿→重评→再生成方案）
  ↓
输出：完整方案文件（11项交付物）
  ↓
保存路径：`04_方案案例/待拍摄/合集名-标题核心短语.md`
```

**执行细节**：
- 预尸检4个问题必须具体回答，不能写"应该不会吧"
- 预案分两条路径处理（v5.4规范）
- 方案文件命名：合集名-标题核心短语.md（不含期数）
- 生成后自动写入 `04_方案案例/待拍摄/` 目录

---

### 阶段5：等待发布后复盘（定时触发）

```
Orchestrator 设置定时任务（T+3天）
  ↓
发布后T+3天，自动触发复盘
  ↓
调用 复盘分析师 Agent（独立Agent·新会话）
  ↓
读取顺序：数据文件 → 盲预测文件 → 逐字稿文件（不可颠倒）
  ↓
输出：预测-实际对比 + 偏差根因分析 + 踩坑记录
  ↓
写入：复盘报告写入原方案文件（不单独建报告）
```

**执行细节**：
- 使用 `automation_update` tool 创建定时任务
- 复盘必须数据先行（v5.11规范）
- 偏差>30%时必须写入记忆宫殿（触发点#10）

---

### 阶段6：账号复盘（定期触发）

```
每周/每月，Orchestrator 调用 账号规划师 Agent
  ↓
读取：账号历史数据 + 已发布方案文件
  ↓
输出：账号数据趋势 + 内容类型效果对比 + 下一阶段选题建议
  ↓
保存：`05_账号复盘/账号复盘-YYYYMMDD.md`
```

## 五、错误恢复机制

### 5.1 重试逻辑

| 错误类型 | 重试次数上限 | 动作 |
|:---------|:-----------|:----|
| 评分<90分 | 3次 | 返回阶段2（带修改意见） |
| 预尸检未通过（稿子修改类） | 2次 | 返回阶段2 |
| Agent执行失败（超时/报错） | 2次 | 重新调用该Agent |
| 双盲差值>10分 | 1次 | 触发仲裁官 |

### 5.2 升级流程

```
重试次数 ≥ 上限
  ↓
Orchestrator 生成详细失败报告
  ↓
输出：
  - 失败原因
  - 失败发生在哪个阶段
  - 已尝试的解决方案
  - 建议的替代方案
  ↓
等待用户决策（继续/修改/放弃）
```

## 六、执行流程（Orchestrator视角）

### 6.1 启动流水线

```
用户输入："开始制作新视频·主题是XXX"
  ↓
Orchestrator 执行：
  1. 生成 pipeline_id: "pipe-" + YYYYMMDD-HHMMSS
  2. 初始化 .cheat-state.json 的 current_pipeline 字段
  3. 输出进度报告（阶段0：初始化完成）
  4. 进入阶段1：选题分析
```

### 6.2 阶段推进规则

| 规则 | 说明 |
|:----:|:-----|
| **质量门禁** | 每个阶段必须通过才能推进（7关✅ / 字数在范围内 / 评分≥90 / 预尸检通过） |
| **上下文隔离** | 评分阶段必须用独立Agent，不能在同一会话中先写稿再评分 |
| **错误恢复** | 失败自动重试，超限后升级 |
| **状态持久化** | 每个阶段完成后更新 .cheat-state.json |

### 6.3 从指定阶段恢复

```
用户输入："启动流水线·从阶段3开始"
  ↓
Orchestrator 读取 .cheat-state.json
  ↓
校验：指定阶段的输入文件是否存在？
  ├─ ✅ 存在 → 从该阶段开始执行
  └─ ❌ 不存在 → 输出缺失文件清单，停止
```

## 九、纪律

1. **不跳过质量门禁**：每个阶段必须通过才能推进
2. **盲评必须隔离**：评分Agent不能在包含写稿上下文的会话中执行
3. **状态必须持久化**：每个阶段完成后更新 .cheat-state.json
4. **错误必须恢复**：不能因为一次失败就停止流水线
5. **不修改盲预测**：预测文件在阶段1生成后，复盘时只能读不能改
6. **触发词唯一**：本Skill的触发词与各子Skill不冲突
