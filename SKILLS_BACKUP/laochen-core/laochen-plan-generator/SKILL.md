# 老陈抖音·方案生成 Skill（v5.2·规范唯一来源）

> **职责边界**：组装方案文件，输出标题/描述/标签/BGM/分镜等。不改稿，不评分
> **触发词**：生成方案/出方案/打包

---

## 一、触发条件

评分通过后说"生成方案" / 评分确认后自动组装

---

## 二、输入

选题评估报告 + 逐字稿(纯净+情绪图) + 评分卡(A/B/C/D) + 预测数据

---

## 三、输出（11项交付物）

```
1. 📋 问题诊断报告
2. 🎬 完整脚本（逐字稿 + 情绪节奏图）
3. 📊 流量预计 + 关键节点
4. ✍️ 发布标题（1主 + 2-4备选）
5. 📝 视频描述（简介）
6. #️⃣ 话题标签（5-8个）
7. 🎵 BGM推荐
8. 📊 内容质量评分卡
9. 🔄 优化前后对比
10. 🎬 分镜说明
11. 📅 复盘模板

已取消：❌封面设计 · ❌即梦Prompt · ❌批量暖场评论
```

---

## 四、标题生成规则

### 核心

好标题 = 制造悬念/仪式感/期待 → 让用户问"是什么/为什么"

### 5种类型（每个必须标注）

| 类型 | 特征 | 示例 |
|:-----|:-----|:-----|
| 悬念型 | 提出问题/矛盾 | "offer薪资差一半，我选了小的" |
| 故事+反差型 | 数字对比/身份反差 | "做了很多年，第一次被新人教育" |
| 洞察型 | 揭示反常识 | "最厉害的人从来不解释自己" |
| 好奇型 | 信息缺口 | "面试官问了一个我从没想过的问题" |
| 系列型 | 属于某系列 | "避坑合集03｜那个最容易忽略的坑" |

### 禁用模式

- ❌ "XXX的N个方法/技巧"（太泛，无信息差）
- ❌ "为什么你应该…"（说教感）
- ❌ 标题里放3条以上干货要点（那是简介或口播的事）
- ❌ 与往期标题高度雷同

### 输出要求

1个主标题（发布用）+ 2-4备选，每个标注类型。

> **75个标题公式库**详见 `references/标题公式库.md`，生成标题时按需查阅。

---

## 五、简介规则（视频第三道钩子）

> 简介 = 提炼视频没说出口的那层洞察。不是口播复述。

| 标准 | 说明 | 示例 |
|:-----|:-----|:-----|
| 提炼洞察 | 行动展示但未讲明的结论 | 口播："我没说，让他问龙虾" → "授人以渔的最好方式是不给他鱼" |
| 不剧透 | 不提前说出结果/答案/金句 | 不出现口播金句关键词 |
| 制造好奇 | 让用户想点进来看"然后呢" | "过了会儿，截图发回来了" |

**禁止**：❌照抄口播 / ❌列3条干货 / ❌重复标题信息 / ❌"评论区留言"话术

**底部固定格式**：
```
#账号标签 #领域标签 #内容标签 #xxx（最多5个）
```

**身份原则**：身份是洞察背书不是万能装饰——与本条洞察相关就写，无关不写。

---

## 六、结尾关注理由规范

> 来源：涨粉踩坑3期记录转化——结尾必须有让人关注的硬理由，不能只说"关注我"。

| 要求 | 示例 |
|:-----|:-----|
| 下期预告具体 | "下期聊大厂offer怎么选"，不说"下期更精彩" |
| 给关注利益 | "关注我，下期直接给你面试话术模板" |
| 身份延续 | 使用当前账号人设锚点，具体身份表述从 `laochen-workstyle` 或项目入口读取 |

---

## 七、标签策略（5-8个）

| 类别 | 数量 | 说明 |
|:-----|:----:|:-----|
| 账号标签 | 1-2 | 从当前账号标签配置读取 |
| 领域标签 | 2-3 | 从当前账号领域关键词读取 |
| 热点标签 | 1-2 | 当期热点 |
| 合集标签 | 1 | #聊职场 / #情商课 等 |

---

## 八、简化互动原则

| 操作 | 频率 |
|:-----|:----:|
| 自己评论 | 1条/期（真实互动） |
| 回复粉丝 | 有则回 |
| 刷评论 | ❌不做 |

---

## 九、执行流程

1. **诊断报告** ← 从选题评估提取
2. **置入脚本** ← writing skill产出
3. **生成标题×3-5** ← 按第四节规则
4. **生成简介** ← 按第五节规则
5. **生成标签5-8个**
6. **推荐BGM** ← 参考writing skill BGM模板
7. **置入评分卡** ← scoring skill产出
8. **优化前后对比**
9. **复盘模板**（预测-实际对比表留空）
10. **版本记录**
11. **（拍摄后补录）校验节**：拍摄完成后，在方案文件末尾追加"拍摄校验"段，记录：
    - 实际拍摄使用的脚本版本号（如v4.0 / v3.0 / 即兴改动）
    - 实际成片时长（秒）
    - 与方案稿的diff（删改/增补的内容摘要，50字内）
    - 记录时间

## 九点五、预尸检（Plan for Failure·v5.3新增）

> **核心问题**：方案阶段发现不了问题，只有复盘时才分析出来——用结果逆推套数据。
> **解决**：拍之前就必须回答"如果失败，可能是什么原因"——把复盘前移。

### 预尸检问题（拍之前必须回答·不能写"应该不会吧"）

| # | 问题 | 必须写出具体答案 |
|:-:|:-----|:----------------|
| 1 | 如果这条视频2秒跳出率>30%，可能是什么原因？ | 不能写"应该不会"→必须写具体场景（如"开头3秒是数据陈述→陌生用户无感"） |
| 2 | 如果整体完播率<5%，稿子的哪个部分最可能劝退？ | 标注具体时间段（如"15-20秒连续说理→无案例→流失"） |
| 3 | 如果涨粉=0，结尾的价值主张哪里不清晰？ | 写出当前结尾钩子→自问"陌生人看完知道为什么要关注吗？" |
| 4 | 如果播放量<500，可能是什么问题？ | 标题？封面？还是内容类型本身不适合账号？ |

### 预尸检记录格式（方案文件必须包含）

在方案文件第2节（🎬 完整脚本）之后、第3节（📊 流量预计）之前，插入：

```
### 2.5. 🔍 预尸检（拍前必填）

| 失败场景 | 可能原因 | 预案 |
|:--------|:--------|:-----|
| 2s跳出率>30% | ___ | ___ |
| 完播率<5% | ___ | ___ |
| 涨粉=0 | ___ | ___ |
| 播放量<500 | ___ | ___ |
```

### 执行规则

1. **预尸检不通过→不生成方案**：4个问题有任一回答是"应该不会吧"→打回重新思考
2. **预尸检记录必须具体**：不能写笼统原因（如"开头不够吸引"），必须写具体场景（如"前3秒是数据陈述→无身份冲突"）
3. **预案必须可执行**：不能写"加强开头"，必须写具体修改动作（如"前3秒改为一个具体身份反差场景"）
4. **🚨 预尸检触发→分流处理（v5.4新增·2026-05-15·第9期复盘教训）**：
   预尸检中任何一项风险的预案，必须先判定属于哪条路径：

   | 预案类型 | 判定标准 | 执行路径 |
   |:--------|:---------|:---------|
   | **拍摄执行类** | 不改逐字稿也能解决（如"读快一点""眼神有力""停顿0.5秒"） | → 写入分镜说明/拍摄注意事项 |
   | **稿子修改类** | 必须改逐字稿才能解决（如"结尾加关注引导""技术术语加大白话消解""开头加身份锚点"） | → **立即改稿→重评→再生成方案，不得跳过** |

   **禁止行为**：
   - ❌ 把"稿子修改类"预案写成拍摄建议（如涨粉=0的预案写"账号身份就是差异化关注理由"→实际稿子里根本没说这句话）
   - ❌ 预尸检写完后直接生成方案
   - ❌ 预尸检只写不改

5. **预尸检验证闭环**：每次发布后复盘时，必须逐条对照预尸检→实际数据，记录哪些命中哪些未命中，写入方案文件复盘节。

## 十、文件命名 + 文件夹规范

### 命名规则（v5.4加固·2026-05-15）

**格式**：`合集名-标题核心短语.md`（不含期数）

**"标题核心短语"定义为方案文件§4中"主标题"的前段关键信息**，截取规则：
- 取标题的前8-15个字作为文件名后半段
- 保证文件名与后台导出的"标题"字段能一眼对应

**正确示例**：

| 主标题 | 文件名 |
|:------|:------|
| 一个具体身份反差场景 | `主题-具体标题.md` |
| 求职和自媒体底层逻辑一样 | `聊职场-求职和自媒体底层逻辑一样.md` |
| 面了300人，985应届和3年经验二本，我每次都选后者 | `聊职场-面了300人我每次都选后者.md` |

**错误示例**：

| 文件名 | 错误原因 |
|:------|:---------|
| `聊职场-学历不够怎么办.md` | ❌ 这是选题描述不是标题。文件名必须使用真实发布标题，否则后台数据对不上 |
| `聊职场-拒了985招了二本.md` | ❌ 同上，实际标题是"第四个候选人推门进来..." |
| `聊职场-面试官最讨厌的3种回答.md` | ❌ 同上 |

### 生成时强制验证

生成方案文件后，必须执行以下检查：

```
1. 读方案文件§4 → 取"主标题"
2. 取主标题前8-15字 → 作为文件名后半段
3. 检查文件名是否匹配主标题 → 不匹配→立即重命名
4. 禁止使用选题关键词、话题描述、内容类型作为文件名
```
- ✅ `领域关键词-具体发布标题.md`
- ❌ `聊职场-第3期：求职和自媒体底层逻辑一样.md`（期数删掉）
- ❌ `第3期：求职和自媒体底层逻辑一样.md`（无合集前缀）

**文件夹规范**：
- `04_方案案例/待拍摄/`：方案已确认、等待拍摄的脚本
- `04_方案案例/已发布/`：拍完复盘后的脚本（自动归档或手动移动）
- 生成方案 → 写入 `待拍摄/`
- 复盘完成后 → 方案文件移动到 `已发布/`

**多版本策略**：
- 同标题只保留最终版本，旧版本命名加`（旧版vX）`后缀，或直接放入已发布/
- 生成前先确认无重名（`list_dir`）

**底部固定格式**（已清理"只说真话"强调语句）：
```
#账号标签 #领域标签 #内容标签 #xxx（最多5个）
```

## 纪律

1. **不改稿**：只组装
2. **不重评**：评分卡直接置入
3. **标题/描述原创**：不照抄口播
4. **命名无期数**：合集名-标题格式
5. **防重名**：生成前list_dir确认
6. **只写待拍摄**：新方案默认写到待拍摄/
