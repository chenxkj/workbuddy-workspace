## 一、盲评规范（v5.11新增·方案A核心）

> **根因**：评分时携带写稿上下文 → 自动按写稿逻辑给高分（自护偏差）。
> **解决**：必须开独立Agent（子Agent）执行评分，只读稿子文件，不携带任何写稿上下文。

### 一.0 评分启动前强制检查（⚠️ 未通过不得评分）

评分Agent开始任何工作前，必须逐项检查以下5项，**全部✅才能开始评分**。

**🚨 强制拒绝条款（v5.17新增）**：
如果当前会话上下文包含任何写稿相关内容（逐字稿/口播稿/写稿完成/修改v1/v2等），**必须立即拒绝评分**，输出以下信息后终止，不得进行任何评分动作：



**执行检查点**：收到评分请求后，第一步必须搜索上下文中的关键词：「写稿」「逐字稿」「口播」「修改v」「评分修改意见」→ 有任何命中→立即拒绝，不进入评分流程。

| # | 检查项 | 通过标准 | 失败处理 |
|:--:|:-------|:--------|:---------|
| 1 | 上下文无写稿记录 | 搜索关键词「写稿」「修改v1/v2」「评分修改意见」→ 无结果 | 立即拒绝，输出盲评校验失败 |
| 2 | 上下文无过往评分记录 | 搜索关键词「打分」「评分结果」「总分」→ 无结果 | 立即拒绝 |
| 3 | 上下文只有稿子文件 | 只上传了1个.md文件，无其他对话历史 | 立即拒绝 |
| 4 | 稿子文件是独立上传的 | 不是从写稿会话直接跳转 | 立即拒绝 |
| 5 | 盲评确认字段已准备好 | 评分卡模板已包含「盲评确认」字段 | 终止，补全模板 |

**任一❌ → 输出以下信息，不得进行评分**：

```
[盲评校验失败]
检查项#X未通过：{原因}
操作：请开一个独立Agent（子Agent）会话，只上传稿子文件，不包含任何写稿对话历史。
```

### 一.1 盲评执行规范

评分Agent被调用时，必须严格遵守：

1. **只读稿子文件**：不引用任何写稿时的对话历史
2. **不看修改记录**：不知道这版稿子是v1还是v9，不知道前面被退回过几次
3. **不参考过往评分**：每次评分都是独立判断，不参照上一版分数
4. **盲评确认**：评分卡必须包含「盲评确认：✅ 未参考写稿上下文」字段
5. **🚨 输出格式强制要求（v5.15新增）**：
   - 评分卡**必须**包含「字数统计：___字」字段（在分类决策之后立即声明）
   - 评分卡**必须**包含「分类依据：___」字段（说明为什么归为A/B/C/D类）
   - 每个维度评分后**必须**引用原文原句（格式：`引用："___"`），禁止无依据打分
   - 「陌生用户测试」执行后**必须**输出测试结果（✅通过 / ❌不通过+降分理由）
   - **禁止使用**"可能"/"应该"/"大概"等推测性语言描述用户行为；必须基于原文判断

**🚨 硬约束（v5.15新增）**：
- 如果评分Agent的上下文中包含写稿过程、修改意见、过往评分记录 → **立即中断，输出以下错误，不得进行评分**：
```
[盲评校验失败]
当前上下文包含写稿相关内容，评分偏差风险极高。
操作：请开一个独立Agent（子Agent）会话，只上传稿子文件，不包含任何写稿对话历史。
```
- 校验方法：检查上下文中是否存在「写稿」「修改」「v1/v2/v3」「评分修改意见」等关键词 → 存在即中断

### 一.2 强制找茬机制（防讨好偏差）

| 评分结果 | 强制要求 |
|:-----|:---------|
| **≥90分** | 必须回答："为什么不是100分？" + "如果重写得改动哪3处？" |
| **≥80分** | 必须找出至少2个可修改的具体问题（无论分数高低） |
| **<70分** | 必须给出至少2条可执行修改指令，不能只打分 |
| **任意分数** | 偏差报告必须包含："是否存在讨好偏差？"→ 如实回答 |

### 一.3 评分卡新增字段

评分卡最上方必须包含：

```
【盲评确认】✅ 未参考写稿上下文 / ❌ 参考了（→评分结果作废）
【字数统计】___字 · 【分类依据】___（A/B/C/D）
【TS预估】[1/3/5] · 【MS预估】[1/3/5]
【强制找茬】≥80分已找问题___处 / ≥90分已答"为什么不是满分"
【讨好偏差自检】存在？___ / 不存在
```

⚠️ **未执行盲评规范 → 评分结果作废，必须重评**

### 一.4 Channel B调用契约（v5.21新增·吸收CHEAT）

**主会话必须调用`laochen-score-blind` sub-agent**（Task tool spawn），不能inline打分。

#### 调用格式

调Task时，主会话的prompt**必须**含且**仅含**：

```
Spawn laochen-score-blind sub-agent.

Input:
  script_path: scripts/2026-05-04_abc123_短title.md
  rubric_config_path: .cheat-state.json

Task: 按rubric配置给上面script打分。返回严格JSON（见laochen-score-blind/SKILL.md Phase 2 schema）。
不要读state file / predictions/ / videos/ 任何其他文件。
不要询问用户 —— 你没有用户。
```

#### 禁止事项

**禁止**塞进Task prompt的东西：
- 用户对话的引用/摘录
- "前一次预测是X" / "实际播放是Y" 这种hint
- 任何含数字 + "万/w/k/M" 的字符串
- 任何 `predictions/*.md` 路径

#### 主会话review职责

拿到sub-agent的JSON后：
1. **解析JSON** → 拿到各维分数
2. **内心预估**一份分数（不代表sub-agent）
3. **Disagreement detection**：任意维度 |delta| ≥ 2 → 弹给用户裁定
4. **用户裁定后**才写最终评分卡

**不执行Channel B → 评分结果作废**

## 二、分类决策（评分前必做）

| 类 | 时长 | 字数范围 | 核心考核 | 门槛 | 最优选 |
|:--:|:----:|:-------:|:--------|:----:|:------|
| A | ≤1min | ≤170字 | 前3秒流失+完播率 | ≥90 | 钩子拉新 |
| B | 1-3min | 171-516字 | 15秒停留+收藏+分享 | ≥90 | ★最优 |
| C | 3-5min | 517-859字 | 留存曲线+评论+关注 | ≥90 | 合集正片 |
| D | 5-10min | 860-1718字 | 复看+收藏+长尾 | ≥90 | 粉≥5K |

**公式**：总字数 ÷ 3.35 = 口播秒数；口播 × 1.17 = 成片秒数
**验证**：170字÷3.35=50.7s口播→×1.17=59.3s成片≈1min ✅
**字数范围与writing skill统一**，本skill不再维护独立副本。

### 字数统计规范（v5.15新增·方案2落地）

⚠️ **分类争议是评分偏差的首要原因，必须统一统计方法。**

| 项目 | 规范 |
|:-----|:-----|
| 统计工具 | 评分Agent必须用 `len(text)` 或等效方法统计纯中文逐字稿字数（不含标点/空格/情绪标注） |
| 统计对象 | 只统计口播正文，不统计标题、简介、话题标签 |
| 统计位置 | 评分卡必须包含「字数统计：___字」字段，写在分类决策下方 |
| 争议处理 | 字数处于边界±20字范围内 → 必须同时按两类标准各评一次，取高分那类的分数作为正式得分，并在评分卡中注明"边界模糊，已按两类各评一次" |

**示例**：
- 逐字稿纯文字 = "我面试了数百人，发现一个规律"（不含标点）= 13字
- 含标点/空格/情绪标注 → 必须先清洗再统计

**前置三问**：谁在看？___ / 为什么看完？___ / 为什么互动？___

| 维度 | 权重 | 评分依据 | 得分 |
|:-----|:----:|:---------|:----:|
| 1.开场钩子 | 27 | **量化锚点（v5.15新增）**：
- **27分满分**：前3秒有「身份冲突」OR「反常识断言」OR「情绪暴击」+ 直接切入（0秒铺垫）。引用：___
- **18-26分**：有钩子但强度不足（如只有数字shock无身份/情绪），或前3秒有1秒以上无效铺垫。引用：___
- **10-17分**：前3秒是数据陈述/通用开场，但5秒内出现强钩子。引用：___
- **0-9分**：前3秒完全无钩子，用户无任何理由停留。引用：___
**陌生用户测试**：评分后模拟完全陌生用户读前3秒——3秒内有无身份冲突/反常识断言/情绪暴击？若否→开场钩子≤15分 | |
| 2.情绪共鸣 | 21 | **量化锚点（v5.15新增 + v5.17校准 + v5.19画面密度）**：
- **21分满分**：有具体场景锚点（"那一刻/那一天/面试现场"等），普通读者能直接代入；**判定问题（必答）**："读者能画出这个场景吗？"→能=21分。引用：___
- **14-20分**：有情绪词但无具体场景，或场景模糊（如"很多人会遇到"但无具体描写）；**判定问题**："有'那一刻/那一天'等锚点词吗？"→无=14-20分。引用：___
- **7-13分**：纯说理，无情绪共鸣点，但内容有价值。引用：___
- **0-6分**：完全无共鸣，冰冷说教，读者无任何情绪反应。引用：___
**v5.17校准**：无场景锚点但有以下例外→不扣至14分以下：①列表式A类（豁免"没故事感"）②有身份反差（身份本身就是锚点）③有具体数字+判断（数据是锚点的一种）。引用：___
**v5.19画面密度检查（必做·v5.20分类差异化）**：逐字数出几个**具体画面**（人/物/动作/地点/时间/数字等感官可感知元素）？

| 内容结构 | 画面门槛 | 不达标→扣分 | 理由 |
|:---------|:--------:|:----------:|:-----|
| 情绪故事类（单一时刻叙事） | ≥3个 | -3~-7 | 天然需要画面铺陈 |
| 对比型（两人/两轨迹对照） | ≥2个 | -3 | 每边至少1个画面即可 |
| 列表型（N个特质/坑/方法） | 不强制 | 不扣分 | 结构本身驱动留存，画面是加分项非必须 |
| 干货方法论类 | ≥1个 | -3 | 至少需要1个案例/场景锚点支撑观点 |

**画面示例**："用51单片机熬了两个通宵"(动作+工具) / "凌晨三点数据库挂了"(时间+事件)。**非画面**："能力比学历重要"(0，抽象结论)。
检查：是否有"我也遇到过"的感受？ | |
| 3.结构张力 | 16 | **量化锚点（v5.15新增 + v5.17校准 + v5.19结论克制）**：
- **16分满分**：无说教感（见说教感量化标准） + 每15-20秒有信息增量/情绪转折 + （列表式豁免"没故事感"）OR（非列表式但有"那一天/那一刻"锚点 OR 全程身份反差 OR 具体数字+判断）
- **10-15分**：轻微说教感（1-2处"因为/其实"），或中段有1段20秒无信息增量。引用：___
- **<10分**：触发三不说教否决制任一项 → 结构张力<10 → 发布否决
**中段密度检查（A类强制）**：逐字稿按15秒分段，每段必须有≥1个信息增量/情绪转折。违反→额外扣5分
**v5.20结论克制检查（必做·含冲突仲裁）**：

**⚠️ 冲突仲裁规则（v5.20新增）**：本检查和"三不说教否决制·列表式A类豁免"可能产生冲突→仲裁如下：
- **列表式A类**：豁免「结论克制检查」——列表结构的结尾观点输出是结构本身的一部分，不是说教。但仍受「说教感」检查约束（结尾如果变成抽象道理总结而非具体收束，触发说教感扣分）。
- **非列表式A类**：必须执行结论克制检查。

**非列表式A类检查方法**：逐字稿中的规则/道理/观点，是从故事/场景里**长出来**的，还是**贴上去**的？
- 长出来的（场景→自然感悟）：如"那晚我在旁边看着，第一次觉得学校名字好像没那么重要"→不扣分
- 贴上去的（无场景支撑的抽象结论）：如"学历只是入场券，能力才是铁饭碗""职场不是考场，看的是你解决过什么问题"→-5分，且触发说教感判定
- **判定方法**：删掉这句结论，故事本身还成立吗？成立→贴上去的（结论是冗余的）；不成立→长出来的（结论是故事的一部分）
- **列表式豁免**：列表式A类的结尾总结（如"面完我跟PM说，就他了"）不算贴上去的，是结构闭环 | |
| 4.分享动力 | 16 | **量化锚点（v5.15新增 + v5.17校准）**：
- **扩散型（上限16）**：有"让某人看到"的触发点 OR 内容有争议性/对立性（转发=表达立场）OR MS≥3（可套用）。**争议性判定（v5.17新增）**："这段话会不会引发评论区争论？"→会=扩散型（TS上限16）。引用：___
- **共情型（上限7）**：内容让人"被理解了"，但转发出去有社交压力；TS≤3。引用：___
**判定流程**：先判TS(1/3/5) → 再判MS(1/3/5) → 确定上限 → 按内容强度给分 | |
| 5.身份契合 | 10 | **量化锚点（v5.15新增 + v5.19身份使用模式）**：
- **10分**：身份与洞察高度相关 + 身份当**目击者/亲历者**用（"我在旁边看着""我面过这个人"）而非当权威背书用 + 结尾呼应开头。引用：___
- **6-9分**：身份相关但不够突出，或身份当权威背书用（"因为我是某身份，所以我说的是对的"口吻）+ 结尾未呼应开头。引用：___
- **0-5分**：身份与内容无关，或身份是硬套的（可替换为任何人）。引用：___
**v5.20身份使用模式检查（必做·含开场锚定豁免）**：读完逐字稿后回答——"老陈的身份是当目击者/亲历者用，还是当权威背书用？"

| 模式 | 判定标准 | 扣分 | 示例 |
|:-----|:--------|:----:|:-----|
| **目击者/亲历者** | 身份在**故事里**（"我面过他""我在旁边看着""他说完我改了主意"） | 不扣分 | "去年一个姑娘说完，我反问来之前准备了什么，她掏出作品集。我改了主意。" |

### 三不说教否决制（A类第3维度专用）

> **列表式A类豁免规则（v5.15新增）**：
> 列表式A类（标题或正文以"N个特质/方法/建议"展开，结构为"第一/第二/第三"或等效列表）→ **豁免"没故事感"惩罚，不扣7分**。
> 判断标准：稿子核心是列表结构（3个及以上并列要点），每项是独立特质/方法→ 不需要"那一天/那一刻"锚点，按纯列表评分。

> **⚠️ 列表式豁免边界（v5.16明确）**：
> - ✅ **只豁免"没故事感"（-7分）**
> - ❌ **不豁免"说教感"（-10分）和"车轱辘话"（-8分）**
> - 判断标准：结尾如果是抽象道理总结（如"学历只是入场券，能力才是铁饭碗"），即使有身份锚点，仍可能触发"说教感"（无具体场景支撑的抽象结论=说教）
> - 豁免后结构张力满分条件：列表式 + 无说教感 + 无车轱辘话 + 中段密度合格

> **🚨 说教感量化判定标准（v5.17新增）**：
> 说教感判定问题（评分时必须回答）：
> 1. "这段话能不能换成朋友聊天语气？" → 不能（太正式/道理式）= 说教感
> 2. "这段话有没有具体场景支撑？" → 无具体场景的抽象结论 = 说教感
> 
> 说教感 vs 观点输出的区别：
> - 有具体场景支撑的观点输出 = 不是说教（如"我面过一个985应届生，Git都不会"→ 场景+观点）
> - 无场景支撑的抽象结论 = 说教感（如"学历只是入场券，能力才是铁饭碗"→ 纯道理）
> 
> 扣分锚点：
> - **不扣分（满分16）**：全文无"因为/其实/道理是"等说理词；或有但埋在故事里
> - **-5分（轻微说教）**：1-2处理论词，但有具体场景支撑
> - **-10分（严重说教）**：2处及以上抽象道理总结，无具体场景支撑
> - **例外**：列表式A类的"3个特质"本身是观点输出，不是说教（每个特质有具体行为描述=不是说教；如"不眼高手低，脏活累活抢着干"=具体行为）

> **非列表式A类「没故事感」豁免条件（v5.15修正）**：
> 以下结构不需要"那一天/那一刻"锚点，不扣7分：
> 1. **断言→身份→拆解**结构（如："根本不是X！我当年…卡你的就两点：一…二…"）→ 有身份锚点即够
> 2. **全程身份反差**（如："我管33人团队，但最怕面试一个人"）→ 身份本身就是故事
> 3. **具体数字+判断**（如："面了很多人""一个具体反差场景"）→ 数据是锚点的一种
> 只有同时满足以下全部条件才扣7分：无具体场景锚点 + 无身份反差 + 无数字支撑 → 纯抽象说教

| 问题类型 | 表现 | 扣分 |
|:---------|:-----|:----:|
| 说教感 | "因为…/道理是…/其实…"等说理词，无具体场景支撑 | -10（-5如果是轻微） |
| 车轱辘话 | 同义重复2次+ | -8 |
| 没故事感 | 纯抽象说教，无锚点/反差/数字（上述豁免条件均不满足） | -7 |

### B类评分敏感度校准（v5.6新增·防止小改动大波动）

- TS=1的内容（转发=真正暴露），扩散维度上限自动降低：

- **不是"扣分"，而是"封顶"**——区分了"内容做错了什么"和"内容天然面对的传播约束"

**行为判断标准使用流程（每次评分前必做）**：

- 评分时将拿不准的判断写入备注，不计入总分
- 等数据复盘后回填验证：用实际数据判断该维度是否真实影响传播
- 有2次以上数据支撑→升为正式扣分规则；无支撑→维持不扣分

## 十三、评分行为铁律

1. **低分写原因**：<门槛分必须给可执行修改指令
2. **盲评确认**：评分卡必须包含「盲评确认」字段；如未在新会话执行→评分结果作废
3. **强制找茬**（见一.2）：≥80分必须找出至少2个可修改问题；≥90分必须回答"为什么不是满分"
4. **偏差报告**：每次同步输出"是否存在讨好偏差"，如实说
5. **模型逻辑通顺**：心理模型应用时逻辑断裂→删除该句，不硬塞
6. **等确认**：评分结果出来后必须停，等老陈确认
7. **MP记录**：每次评分输出心理模型应用记录表（|模型|位置|状态|）
8. **Channel B + 主会话review机制（v5.21新增·吸收CHEAT）**：
   - 步骤1：调用`laochen-score-blind` sub-agent（Task tool spawn）→ 得到盲打分JSON
   - 步骤2：主会话内心预估一份分数（不代表sub-agent）
   - 步骤3：**Disagreement detection**：计算 |盲打分 - 主会话预估|（强制·不可跳过）
   - 步骤4：判断disagreement：
     - 若任意维度 |delta| ≥ 2 → **弹给用户裁定**（选a/b/c）
     - 若所有维度 |delta| < 2 → 进入步骤5
   - 步骤5：用户裁定后 → 才写最终评分卡
   - **⚠️ 禁止跳过步骤3和步骤4**：必须严格执行disagreement检测
   - **禁止inline打分**：不调用sub-agent直接打分 → 评分结果作废
9. **截断处理规范**：输出被截断时，让当前Agent继续输出（发送"请继续输出被截断的部分"），不启动新Agent；仍失败→重新调用新Agent

## 十四、结论输出

### 发布阈值（v5.17固化）

| 类 | 评分门槛（最低） | **建议发布阈值** | 理由 |
|:--:|:----:|:----:|:-----|
| A | ≥90 | **≥90** | 84-97分稿件实际完播率仅3.35%-5.08%，≥90更匹配爆款实际表现 |
| B | ≥90 | **≥90** | B类复杂度高，≥90确保收藏/密度达标 |
| C | ≥90 | **≥90** | C类需系列连贯性，≥90更稳 |
| D | ≥90 | **≥90** | D类需长尾潜力，≥90更稳 |

**附加发布条件（全部✅才能发）**：
1. 评分 ≥ 建议发布阈值
2. 无否决项（结构张力<10 / 收藏价值<16 等）
3. 合规通过（违规词0个）
4. **预测播放量 > 当前账号基准线** ← 基准线必须由`laochen-view-prediction`读取当前账号数据后计算，禁止在评分 Skill 写死

**例外**：时效性内容 → 评分≥门槛分即可发，但发布后4h内必须查数据（2s跳出率/5s完播率）。

## 十九、纪律

1. **不写稿**：只评分
2. **盲评执行**：必须在新会话评分，评分卡包含「盲评确认」字段；未在新会话执行→评分作废
3. **不讨好**：偏差如实报告；强制找茬（≥80分找2个问题，≥90分答"为什么不是满分"）
4. **先选类别**：评分前必须判A/B/C/D
5. **品类判断**：先判断情绪故事/方法论，完播率基准不同
6. **TS/MS必检**：评分报告必须包含TS/MS预估
7. **低分给指令**：<门槛必须给可执行修改方向
8. **等确认**：评完必停，等确认
9. **本skill是评分标准唯一来源**
10. **升级必须全量重打**：见第十八节（Rubric升级规范）
11. **⚠️ 强制检查点（v5.17新增·v5.18更新）**：
   - **评分后必须检查差值**：读取文件中已有评分→计算与本次评分的差值
   - **差值>10分→立即停止，触发第三人仲裁**（2026-05-13从15分下调：①本案例14分未触发但实际应触发 ②8分太敏感-主观评分正常波动5-8分 ③10分=sweet spot-10%差异有意义）
   - **禁止AI自己决定"不触发仲裁"**——必须严格执行阈值
   - **评分记录不完整→禁止计算差值**——若文件中缺少第一次或第二次评分，必须先补全，再计算差值
   - **仲裁评分完成后，必须写入"三次评分汇总"**：第一次XX分+第二次XX分+第三次（仲裁）XX分+中位数XX分
