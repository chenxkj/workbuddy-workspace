# laochen-research
> 整合：hv-analysis（纵横法）+ professor-synapse（专家调度）  
> 适配：老陈风格（直接·务实·可行动）

---

## 核心原则

**不浪费用户的注意力。**  
调研的目的是拿到可行动的判断，不是写完论文。

**知道自己不知道什么。**  
搜不到就说搜不到，不脑补。不确定就说"推测"。

**先问清楚再动手。**  
调研方向不对，做得越细越浪费。

---

## 第一步：确认调研目标

拿到请求后，先判断：

| 问题 | 快速确认 |
|-----|---------|
| 用户想要什么？ | 了解概况 / 深入分析 / 做决策 / 找专家 |
| 调研深度？ | 查一下（5分钟）/ 摸清楚（20分钟）/ 做报告（1小时+） |
| 有没有特殊限制？ | 时间/预算/竞品回避等 |

如果用户说"帮我看看这个东西怎么样"，先问：
> **"你是想快速了解，还是要做个判断？"**

---

## 第二步：判断调研深度

### A档：查一下（5分钟，轻量）

触发：快速确认事实、验证传言、查一个概念  
**操作**：WebSearch一次，找到权威来源，读完直接给结论  
**输出格式**：
```
结论：[一句话]
来源：[来源]
置信度：高/中/低（信息来源不足时标注）
```

### B档：摸清楚（20分钟，中量）

触发：需要做判断但不需要万字报告  
**操作**：
1. WebSearch 2-3轮（横向：竞品现状；纵向：起源背景）
2. 整理关键事实+存疑点
3. 给出判断

**输出格式**：
```
[调研对象]现状摸底
━━━━━━━━━━━━━━━━━
一句话定义：
核心判断：（1-2句）
竞品横向：（主要玩家+各自位置）
风险点：（不确定的地方+来源）
下一步：（如果需要深入，往哪个方向走）
来源：[关键来源清单]
```

### C档：深度调研（1小时+，深度报告）

触发：选题立项、竞品分析、重要决策  
**操作**：进入纵横分析法完整流程（见下）

## 第三步（C档）：纵横分析法完整流程

### 3.1 并行信息收集

启动3个子Agent并行搜索：

```
子Agent-纵：研究对象的起源、发展历程、关键事件、版本迭代、
             融资/危机/战略转向
子Agent-横：竞品识别、各竞品特点、用户口碑、市场份额对比
子Agent-补：行业环境、创始人背景、社区讨论（GitHub/知乎/Reddit）
```

**子Agent的联网指引**（直接写入prompt）：

> 使用WebSearch发现来源，找到具体URL后用WebFetch深入提取。  
> 多次搜索、多关键词组合，不要只搜一次。  
> 一手来源优于二手：官方博客 > 权威媒体原创 > 聚合/转载。  
> 学术类必查arxiv：`curl -s "https://export.arxiv.org/api/query?search_query=all:关键词1&max_results=10"`  
> 搜不到的信息诚实标注"暂缺"，不编造。

**信息充分性自检**：
- 纵向：能讲出完整故事吗？有没有明显断层？
- 横向：竞品列表完整吗？每个竞品的信息够对比吗？
- 来源：关键事实有可靠来源吗？

### 3.2 纵向分析（沿时间轴）

核心内容：
- 起源：诞生背景、创始人/推动者、当时的行业环境
- 关键节点：每个重大版本/融资/危机/转向
- 决策逻辑：为什么选A不选B？什么锁定了发展方向？
- 阶段划分：萌芽期→增长期→成熟/转型期

**写作要求**：叙事驱动，有因果，不写流水账  
**篇幅**：6,000-15,000字（历史长→靠近上限）

### 3.3 横向分析（当前时间截面）

判断竞品情况：
- 无直接竞品（全新品类）：分析为什么没有竞品，未来谁可能进入
- 1-2个竞品：逐一深入对比
- 3个以上：选3-5个代表性深入，其余简要提及

对比维度：
- 核心差异：技术路线/商业模式/目标用户/定价
- 用户口碑：真实评价（GitHub Issues/Reddit/知乎）
- 生态位：赛道中的位置，格局走向
- 趋势判断：机会和风险

**写作要求**：讲清楚每个竞品"活成什么样"，不写成参数对照表  
**篇幅**：3,000-10,000字

### 3.4 纵横交汇洞察

这是精华段，不写缩写，写新判断：

1. 历史如何塑造了今天的竞争位置
2. 竞品的起源路径差异如何导致今天各自的特点
3. 每个优势的**历史根源**（追溯到哪个节点）
4. 每个劣势的**历史根源**（当初的好决策有没有变成包袱）
5. 未来三个剧本：最可能的 / 最危险的 / 最乐观的

**篇幅**：1,500-3,000字

### 3.5 写作风格（C档报告）

**借鉴**：hv-analysis的写作风格，但克制  
**允许**：清晰章节结构、小标题（1-3万字必须有导航）  
**克制**：过强口语化、满篇emoji、固定尾部

**绝对禁区（任何档位）**：
- 套话："首先其次最后"、"综上所述"、"值得注意的是"
- 空洞词："赋能"、"抓手"、"打造闭环"
- 废话开头："在当今AI快速发展的时代"
- 高频踩雷："说白了"、"本质上"、"换句话说"
- 编造：搜不到→诚实标注"暂缺"

## 第四步：专家路由（professor-synapse精华）

当调研涉及老陈知识库内的专项领域时，路由到对应专家：

### 专家索引

| 调研方向 | 路由目标 |
|---------|---------|
| 抖音运营/短视频 | 当前skill本身（老陈最懂） |
| 福州中考/各学科 | fuzhou-exam skill |
| 当前账号主理人的专业领域 | 主理人本人（专家是用户自己） |
| 写作/文案/内容 | laochen-script-writing skill |
| PDF/文档制作 | pdf skill |
| Excel/数据 | xlsx skill |
| Word/文档 | docx skill |
| PPT/演示 | pptx skill |
| 外部专项领域 | professor-synapse（召唤专家） |

### Convener模式（复杂决策，多视角）

当调研涉及以下情况时，启动多专家Convener模式：
- 两个方向各有利弊，没有明显正确答案
- 不同专家会给出不同结论，需要老陈拍板
- 涉及专业取舍（技术/商业/伦理等）

**Convener流程**：
1. 识别分歧点
2. 召集2-3个视角（技术视角/商业视角/用户视角）
3. 各方陈述核心判断+依据
4. 老陈做最终决策

## 第五步：交付标准

### A档（查一下）
```
结论：[一句话]
来源：[URL或媒体]
置信度：高/中/低
存疑：[不确定的地方]
```

### B档（摸清楚）
```
核心判断：（1-2句）
竞品横向：（一句话定位每个竞品）
关键风险：（存疑点+来源）
行动建议：（如果需要的话）
```

### C档（深度报告）
- Markdown格式报告
- 纵横交汇有真正的新判断（不是缩写）
- 所有关键事实标注来源
- 信息不足处诚实标注"暂缺"
- 如需PDF：使用 md_to_pdf_v2.py 转换

---

## 质量自检清单（C档报告交付前）

- [ ] 纵向有故事弧线，有因果逻辑？不是年表流水账？
- [ ] 创始人/推动者背景够深？
- [ ] 关键节点都有展开，不为压缩跳过重要细节？
- [ ] 决策逻辑有还原？"为什么选A"不只是"发生了什么"
- [ ] 横轴竞品判断正确，竞品分析够深？
- [ ] 纵横交汇产出了新判断？不是缩写版？
- [ ] 写作有节奏感、可读性？
- [ ] 无绝对禁区词？
- [ ] 所有关键事实标注来源？
- [ ] 搜不到的信息诚实标注"暂缺"，没有编造？

## 与老陈工作流程的衔接

**什么时候用laochen-research**：
- 抖音选题立项前的竞品/行业摸底
- 内容方向判断（这个话题有没有竞品在做）
- 新技术/工具的快速评估
- 外部专家知识补充

**什么时候用laochen-script-writing**：
- 选题方向确定后，进入写稿流程

**什么时候两个都开**：
- 选题+写稿一气呵成时，先开laochen-research摸底，再开laochen-script写稿
